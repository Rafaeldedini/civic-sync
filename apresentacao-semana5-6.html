CIVIC-SYNC

API REST + Dashboard de Monitoramento

O CIVIC-SYNC é um sistema distribuído de monitoramento de crises e desastres naturais projetado para cidades inteligentes. Sensores IoT espalhados pela cidade coletam dados em tempo real — nível de rios, umidade do solo, deslocamento de encostas e temperatura de áreas florestais — e o sistema processa, classifica e alerta automaticamente sobre riscos ambientais.

Nesta entrega, apresentamos a camada de API REST que expõe os dados processados, e o dashboard web que permite visualizar alertas, estatísticas e leituras em tempo real com atualização automática a cada 2 segundos.

Antes de apresentar o trabalho desta etapa, um resumo das entregas anteriores que formam a base do sistema:

🏗️
Semana 1-2 — Arquitetura, Fila e Persistência
Definimos a arquitetura de microsserviços usando npm workspaces como monorepo. Configuramos a infraestrutura com Docker Compose (PostgreSQL 15 + Redis 7). Criamos a API de ingestão com Fastify 5, validação rigorosa com Zod, e duas filas no BullMQ: uma para persistência crua e outra para processamento. O worker de persistência usa Prisma ORM para salvar os dados brutos no PostgreSQL.

✅ 100% — Entregue 13/04

⚙️
Semana 3-4 — Score Engine e Classificação de Alertas
Desenvolvemos o Score Engine, um módulo que avalia cada leitura de sensor e atribui uma pontuação de risco de 0 a 100 baseada em limiares configuráveis por tipo de sensor. O sistema classifica automaticamente em 4 níveis de severidade: Normal, Atenção, Alerta e Crítico. Criamos o mock sensor que simula 10 sensores IoT com dois modos: normal e crise. Os resultados são persistidos como AlertAssessments no banco.

✅ 100% — Entregue 27/04

Semana 5-6 — Entrega Atual

API REST — 7 Endpoints para consumo de dados

A API foi construída em Fastify 5 com TypeScript strict. Todas as rotas possuem validação de entrada e saída via Zod (type-safe). O CORS está habilitado para permitir acesso do dashboard. A API roda na porta 3001 e serve como ponto central de consulta do sistema.

Semana 5-6 — Entrega Atual

Dashboard — Monitoramento em Tempo Real

O dashboard é uma Single Page Application (SPA) em HTML puro que consome a API REST via fetch(). Ele atualiza automaticamente a cada 2 segundos sem recarregar a página, mostrando dados ao vivo do sistema. O design usa dark mode com gradientes, animações de entrada e tipografia profissional via Google Fonts (Inter).

📊
4 KPI Cards com Animação
Leituras processadas, estado crítico (com indicador pulsante quando há alertas), total em alerta e atenção. Números animam suavemente ao atualizar, com gradientes de cor por severidade.
🍩
Gráfico Doughnut (Chart.js 4)
Distribuição visual por severidade: Normal (verde), Atenção (amarelo), Alerta (laranja), Crítico (vermelho). Tooltip mostra percentual. Label central com o total de leituras. Atualiza em tempo real.
📡
Live Feed — Tabela de Últimas Leituras
Mostra as 10 leituras mais recentes com tipo de sensor, valor, unidade, score de risco e badge de severidade. Cada linha entra com animação fadeUp escalonada.

Arquitetura Distribuída do Sistema

Planejamento

Semana 7-8 — Próximos Passos

A próxima (e última) etapa foca em tornar o sistema robusto para produção, com observabilidade, proteção e resiliência:

1
Logs Estruturados (Pino)
Substituir todos os console.log por um logger profissional (Pino) com saída JSON em produção e pretty-print em desenvolvimento. Cada log terá contexto: jobId, sensorId, tipo, tentativa.
2
Hardening da API
Implementar Rate Limiting (máx. 200 req/min) para proteção contra DDoS. Health Check profundo que testa conexão com Postgres e Redis. Headers de segurança via Helmet.
3
Tolerância a Falhas (Retry + DLQ)
Configurar retry automático com backoff exponencial no BullMQ (8 tentativas, ~8.5 min). Dead Letter Queue para jobs que falharam definitivamente. Graceful shutdown em todos os serviços.
4
Demo de Engenharia de Caos
Preparar roteiro de demonstração: derrubar o PostgreSQL, provar que a API continua aceitando dados, e quando o banco voltar os dados são recuperados automaticamente.
